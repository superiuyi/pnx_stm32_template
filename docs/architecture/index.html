01 · 为什么分层

不分层，最后会变成“谁都不敢改”

分层不是为了好看，而是把变化关进小盒子里： 换板子、换引脚、换 IMU、加线程，都只动一小块。

反面教材

一个 main.cpp 管所有事

改动会传染
业务逻辑 HAL_GPIO_WritePin 引脚宏 RFID 协议 线程创建 CubeMX 配置 JSON 解析 电机控制 PID 串口收发

换一个引脚，要在这个文件里全局搜索；CubeMX 重新生成，还可能把手写代码覆盖掉。

02 · 架构地图

每一层，只回答一个问题

三栏：先点“层”，再点这一层的“子文件夹”，右边展开文件、关键接口、谁在用它、它依赖谁。 红色标签是“它不负责”的事——边界比功能更重要。

03 · 请求旅程

跟着一次请求，穿过整个工程

选一个场景，点“下一步”，看控制流从复位、RTOS、应用线程一路走到硬件。 每一步都会告诉你“现在在哪一层”。

这张图不是运行时调用链，而是 CMake 的 target 依赖。 点节点看它负责什么；INTERFACE 库只是“清单”，不是箱子。

05 · 加功能向导

我想改点东西，该动哪一层？

选一个任务，得到“改哪层、改哪些文件、别动哪里、怎么验证”的清单。 这是最实用的部分。

06 · 文件词典

每个子文件夹，到底是干嘛的

55 个子文件夹 + 100 多个文件/接口条目。按层筛选，或直接搜“spi / pwm / dsp / buzzer / wrapper”。 点卡片展开“它做什么、关键文件、什么时候会用到”。
